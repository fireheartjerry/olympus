# Fire Contract Foundation Acceptance

## Scope

This slice adds side-effect-free contracts and deterministic validation for:

- goals and cognitive evidence;
- the Jerry-model substrate;
- objective contracts and execution graphs;
- selective memory;
- Fire persona and identity lineage;
- takeover interpretation/session state;
- self-improvement promotion;
- evaluation metrics.

It deliberately does not add persistence, workflows, capabilities, grants, providers, deployment, or live effects.

## Compatibility

The implementation remains under `olympus.*` while `fire.*` exposes compatibility facades. This follows the existing reversible rename strategy: live imports, persisted identifiers, migrations, and deployment names do not move underneath the production authority boundary.

## Package-local evidence

At package generation time:

- 28 focused tests passed;
- all source files compiled under Python 3.13;
- twenty-five public JSON Schemas were generated;
- schema generation was deterministic;
- no capability catalog or deployment file was modified.

These results are not repository acceptance. The integrating agent must run all current Python and Helm gates from a clean branch, build and inspect the wheel, and prove no production behavior changed.

existing `tests/discord/test_contracts.py` under rootdir-based collection. The
repository already resolves exactly this collision for
`tests/authentication/test_service.py` against `tests/discord/test_service.py`
by making the directory a package, so `tests/objectives/__init__.py` was added
to match that precedent rather than renaming the packaged test.

## Rollback

The overlay adds new files only. Before later slices depend on them, rollback removes those files and their documentation. After persistence or other code depends on the contracts, rollback requires a compatibility release rather than deletion.
